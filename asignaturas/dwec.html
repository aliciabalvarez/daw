Desarrollo web en entorno cliente

Resúmenes por tema

    Tema 1

    Arquitecturas y lenguajes de programación en clientes web.

    Introducción a los lenguajes de diseño web en el entorno cliente: características, limitaciones, seguridad y herramientas para empezar a programar en JavaScript. El hilo conductor es la modernización de una web a Web 2.0: más interacción, interoperabilidad y aplicaciones más ricas y no intrusivas.

    1.- Desarrollo web.

    La web la creó Tim Berners-Lee en el CERN en 1989, junto a Robert Cailliau, como herramienta colaborativa para el conocimiento científico. Se basaba en el concepto de hipertexto. Su expansión se apoyó en aportaciones posteriores como la interfaz MOSAIC de la NCSA.

    El W3C (consorcio con sede en el MIT) es el responsable de desarrollar y mantener los estándares web.

    Por "Web" se puede entender…¿Es el uso habitual?
    El proyecto inicial del CERNNo
    El conjunto de protocolos desarrollados en ese proyectoNo
    El espacio de información formado por todos los servidores interconectadosSí
    Concepto clave

    El Desarrollo Web es un campo multidisciplinar: influyen las nuevas tecnologías, el diseño gráfico, la programación, las redes, el diseño de interfaces y la usabilidad, entre otros.

    Autoevaluación

    ¿Cuando nos referimos a la Web estamos hablando de?

    Espacio de información que nos proporcionan los servidores a través de Internet. Es el significado habitual de «la Web».

    ¿Qué es hipertexto?

    Un texto que al pulsar en él conduce a otro texto. Es un enlace. De ahí viene HTML: HyperText Markup Language.

    1.1.- Áreas.

    Cinco áreas cubren la mayor parte del Diseño Web. Su peso varía según el tipo de sitio (una web personal no tiene las mismas consideraciones económicas que una tienda online).

    ÁreaQué abarca
    ContenidoForma y organización del contenido: cómo se escribe, se estructura y se presenta con lenguajes de marcas como HTML.
    VisualLa plantilla del sitio, generada normalmente con CSS, con elementos gráficos de decoración o navegación. Es la más visible, pero no la más importante.
    TecnologíaSobre todo los elementos interactivos construidos con técnicas de programación.
    DistribuciónVelocidad y fiabilidad con que se sirve el sitio; depende del hardware, el software y la arquitectura de red.
    PropósitoLa razón de ser del sitio, normalmente económica. Debe guiar las decisiones del resto de áreas.
    Metáfora de la pirámide

    El contenido son los ladrillos; la base se apoya en lo visual y lo tecnológico; y el propósito (normalmente económico) es el objetivo final.

    Los sitios web actuales siguen un modelo cliente-servidor con tres elementos:

    ElementoQué incluye
    Lado del servidor (server-side)Hardware y software del servidor web y sus tecnologías: desde CGI en Perl hasta aplicaciones Java, bases de datos o Node.js (JavaScript en el servidor).
    Lado del cliente (client-side)Los navegadores y las tecnologías que interpretan: HTML, CSS y JavaScript, para presentación e interactividad. Es el foco de este módulo.
    La redLos elementos de conectividad que hacen llegar el sitio al usuario.

    2.- Lenguajes de programación en clientes web.

    Las tecnologías client-side se ejecutan en el cliente (normalmente el navegador); las server-side las ejecuta o interpreta el servidor. No compiten: son complementarias, y lo habitual es combinarlas.

    Ejemplo típico: un formulario

    Se valida en el cliente antes de enviarlo (respuesta inmediata, menos frustración para el usuario) y se vuelve a validar en el servidor para asegurar la integridad. El guardado en la base de datos lo gestiona el servidor.

    Dentro de los lenguajes de cliente hay dos variantes:

    • Lenguajes para dar formato y estilo (HTML, CSS…).
    • Lenguajes para aportar dinamismo: los lenguajes de scripting. El módulo se centra en JavaScript, el más usado y soportado por casi todas las plataformas.

    Un lenguaje de script es un lenguaje para dar instrucciones a un programa que ya existe. JavaScript da instrucciones al navegador, que lee el código y lo ejecuta.

    ComportamientoJavaScript

    Contenidotexto, imágenes, vídeos…

    2.1.- Características.

    JavaScript en el cliente no sustituye a la programación de servidor. Motivos:

    1. No puede escribir ficheros en el servidor. Prepara los datos y se los cede al lenguaje de servidor.
    2. No todos los clientes ejecutan JavaScript (algunos lectores, móviles, buscadores…). La web debe seguir funcionando con JavaScript desactivado; JS mejora la experiencia, no la sostiene.
    3. AJAX integra cliente y servidor: desde el navegador, de forma asíncrona y en segundo plano, pide o envía datos al servidor y actualiza partes de la página con la respuesta. Así funciona hoy la mayoría de webs.

    Para qué está pensado JavaScript:

    • Reaccionar a la interacción del usuario con formularios y enlaces.
    • Distribuir pequeños grupos de datos con una interfaz amigable.
    • Controlar ventanas, marcos, plug-ins o applets según lo que elija el usuario.
    • Preprocesar datos en el cliente antes de enviarlos.
    • Modificar estilos y contenido de forma dinámica e instantánea.
    • Solicitar ficheros al servidor y enviar peticiones de lectura/escritura a los lenguajes de servidor.

    Además, hay intérpretes de JavaScript integrados en muchas aplicaciones de uso cotidiano, no solo en páginas web.

    Autoevaluación

    ¿Podríamos escribir con JavaScript un fichero de texto directamente en el servidor?

    De ninguna manera. JavaScript prepara y envía los datos (incluso con AJAX), pero quien escribe en el servidor es el lenguaje de servidor.

    2.2.- Compatibilidades.

    JavaScript lo interpreta el cliente, así que el mismo script debe funcionar igual en Chrome, Firefox, Safari, Opera, etc. Cada navegador soporta características distintas y tiene sus propios fallos (de la plataforma o del navegador). Con los scripts de servidor, en cambio, tenemos control total de su interpretación.

    Pista

    Muchas incompatibilidades no vienen del JavaScript sino del HTML. Ajusta tu HTML al estándar W3C y compruébalo con el validador del W3C.

    Limitaciones a tener en cuenta:

    • No todos los navegadores soportan scripting en el cliente.
    • Algunos dispositivos móviles no ejecutan JavaScript.
    • Las implementaciones de los grandes navegadores no son totalmente compatibles entre sí.
    • El usuario puede desactivar JavaScript manualmente.
    • Algunos navegadores de voz no interpretan JavaScript.

    2.3.- Seguridad.

    Para frenar scripts maliciosos, los navegadores aplican dos restricciones:

    RestricciónQué implica
    Espacio seguro de ejecución (sandbox)El script solo puede hacer tareas relacionadas con la web; nada de tareas genéricas como crear ficheros.
    Política de mismo origenLos scripts de una web no pueden acceder a datos (usuarios, contraseñas, cookies) de otra web.
    Concepto clave

    La mayoría de agujeros de seguridad son infracciones de la política de mismo origen o del espacio seguro de ejecución.

    Lo que JavaScript no puede hacer (y que refuerza su seguridad):

    • Modificar o acceder a las preferencias del navegador, la apariencia de la ventana, la impresión o los botones del navegador.
    • Lanzar aplicaciones en el ordenador del cliente.
    • Leer o escribir ficheros o directorios del cliente (salvo cookies).
    • Escribir ficheros directamente en el servidor.
    • Capturar datos de un streaming del servidor para retransmitirlos.
    • Enviar emails de forma invisible sobre los visitantes (sí puede mandar datos a una aplicación de servidor que los envíe).
    • Interactuar directamente con los lenguajes de servidor.
    • Acceder a páginas de otros dominios.
    • Proteger el origen de las imágenes de la página.
    • Implementar multiprocesamiento o multitarea.

    XSS (Cross-Site Scripting): vulnerabilidad que viola la política de mismo origen. El atacante consigue inyectar código malicioso en la página que ve la víctima (por ejemplo, desde la base de datos que consulta). A esto se suman los defectos de navegadores y plugins, que los atacantes aprovechan para ejecutar scripts en el sistema del usuario.

    La implementación de seguridad más importante radica en el motor de ejecución de JavaScript implementado en el navegador, porque es quien ejecuta el código. Ejemplos de motores:

    • Active Script de Microsoft (soporta JScript, con características fuera del estándar ECMA).
    • El toolkit Qt (C++), que incluye un intérprete de JavaScript.
    • Java JDK 1.6, con el paquete javax.script.
    • Los motores de cada navegador (Mozilla, Google, Opera, Safari…). Hoy se diferencian por su velocidad y por el aislamiento entre pestañas y ventanas.

    Autoevaluación

    Indica en dónde radica la implementación de seguridad más importante cuando se ejecuta cualquier código de JavaScript:

    En el motor de ejecución de JavaScript implementado en el navegador. «El navegador» es casi correcto, pero la pieza concreta que ejecuta el código y aplica las restricciones es el motor.

    3.- Herramientas y utilidades de programación.

    Lo mejor para aprender es escribir HTML y JavaScript en un editor de texto. Se desaconsejan los editores WYSIWYG, porque se centran en contenido y presentación, no en el código. Al elegir editor, fíjate en que guarde fácilmente con extensión .html y en la codificación que usa.

    No hace falta un IDE: un editor ligero con estas características es suficiente.

    Completado automáticoSugiere opciones mientras escribes.

    El navegador también es herramienta

    No necesitas conexión a Internet para probar tus scripts. Lo importante son las herramientas de desarrollo del navegador: consola con los errores, estructura del documento y, en algunos casos, depuración.

    4.- Integración de código Javascript con HTML.

    Hay dos formas de añadir JavaScript a una página.

    1. Código dentro de la etiqueta <script> (el atributo type indica el lenguaje):

    <script type="text/javascript">
    // El código de JavaScript vendrá aquí.
</script>

    2. Fichero externo .js referenciado con el atributo src. Es la forma recomendada:

    <script type="text/javascript" src="miScript.js"></script>
    Ventajas del fichero externo
    Separa el código de la estructura de la página.
    Permite compartir código entre páginas y centralizar la depuración.
    Más claridad y modularidad.
    Carga más rápida: si varias páginas usan el mismo .js, se toma de la caché del navegador.
    Ojo
    • Las etiquetas <script> y </script> son obligatorias también con src.
    • No escribas código entre ellas cuando uses src.
    • Para varios ficheros, repite la etiqueta una vez por fichero.

    Tipos de ruta para el fichero:

    TipoEjemploSignificado
    Absolutasrc="http://www.midominio.com/miScript.js"URL completa: dominio y ruta dentro del dominio.
    Relativasrc="./js/miScript.js"Desde la carpeta del .html, dentro del directorio js.
    Mismo directoriosrc="miScript.js"El .js está junto al .html.

    Para navegadores sin soporte de JavaScript existe <noscript>Texto informativo</noscript>, aunque hoy es poco habitual necesitarlo.

    Ejemplo HTML5 con el código dentro de index.html:

    <!DOCTYPE html>
<html lang="es-ES">
    <head>
        <meta charset="UTF-8">
        <title>Hola mundo desde DWEC</title>
        <script>

            }
        </script>

    </body>
</html>

    El mismo ejemplo con fichero externo:

    const saludar = () => {
    alert('Hola mundo desde DWEC');
}
    <!DOCTYPE html>
<html lang="es-ES">
    <head>
        <meta charset="UTF-8">

    ¿Se puede proteger el código JavaScript?

    No. Todo lo que descarga el navegador es visible: basta con abrir la ruta del .js. Como mucho se puede ofuscar (quitar saltos de línea y espacios, nombres ininteligibles, recursividad…), normalmente con una herramienta que además lo comprime. Lo recomendable es cambiar el enfoque: añadir un aviso de copyright, comentar bien el código y compartirlo con la licencia que elijas, por ejemplo en GitHub.

    Errores comunes del tema

    ❌ Error✅ Corrección
    Escribir código dentro de un <script src="..."> Si usas src, deja la etiqueta vacía. El código va en el .js o en otro <script> aparte.
    Omitir </script> al enlazar un .js <script src="miScript.js"></script>: la etiqueta de cierre es obligatoria.
    src="miScript.js" cuando el fichero está en la carpeta js/ src="./js/miScript.js": la ruta relativa parte de la carpeta del .html.
    Validar el formulario solo en el cliente Validar en el cliente (experiencia de usuario) y en el servidor (integridad).
    Pensar que JavaScript guarda ficheros en el servidor JS prepara y envía los datos (p. ej. con AJAX); el lenguaje de servidor es quien los guarda.
    Hacer una web que solo funciona con JavaScript activado La web debe ser funcional sin JS; JavaScript mejora la experiencia, no la sustenta.
    Creer que mover el código a un .js externo lo oculta Cualquiera puede abrir el .js. Solo cabe ofuscarlo, nunca ocultarlo.

    Tema 2

    Estructura del lenguaje javascript.

    Fundamentos de JavaScript: comentarios, variables y constantes, tipos de datos y sus conversiones, operadores, estructuras de control y bucles. Termina con un primer ejemplo completo.

    1.- Fundamentos de javascript.

    Breve historia de JavaScript y de su estándar, ECMAScript:

    FechaHito
    Mayo de 1995Brendan Eich, en Netscape, crea el lenguaje en unos 10 días (se llamó primero Mocha).
    Septiembre de 1995Se lanza como LiveScript en Netscape Navigator y poco después pasa a llamarse JavaScript.
    1997Se estandariza en ECMA: nace ECMAScript (ES1).
    1998ES2, ajustes menores.
    1999ES3, la versión que se usó durante muchos años.
    2011ES5.1 (modo estricto, JSON, nuevos métodos de arrays…).
    2015ES6 (ES2015): let, const, funciones flecha, plantillas de cadenas, desestructuración… Es la versión de referencia del módulo.
    Concepto clave

    JavaScript añade la tercera capa del desarrollo web: HTML da la estructura, CSS la presentación y JavaScript el comportamiento.

    Desde ES6 sale una versión nueva cada año (ES2016, ES2017…). El módulo se ciñe a ES6, que soportan todos los navegadores modernos.

    ¿Quién desarrolló JavaScrip?

    Brendan Eich, cuando trabajaba en Netscape, en 1995.

    1.1.- Comentarios en el código.

    Los comentarios son notas para quien lee el código; el intérprete los ignora. Hay dos tipos:

    // Comentario de una sola línea

/*
    Comentario de
    varias líneas
*/
    Pista

    Hoy se prefiere que el código se explique solo (autodocumentado): mejor una función con un nombre claro que un comentario explicando qué hacen unas líneas. Además, los comentarios ocupan espacio y hacen el fichero más pesado de descargar.

    1.2.- Constantes y variables.

    Una variable es un contenedor con nombre (identificador) que guarda un valor que puede cambiar. Una constante guarda un valor que no puede cambiar.

    Reglas para los nombres
    Solo letras, números y guion bajo: [a-zA-Z0-9_].
    No pueden empezar por número.
    No pueden ser palabras reservadas (if, for, let…).
    Que sean descriptivos y en lower camel case: edadUsuario, precioFinal.

    Se declaran con const (constantes), let o var (variables). Una variable declarada sin valor vale undefined.

    const pi = 3.14;
var edad = 18;
let nombre = "Bob Esponja";
    var (antigua)let (ES6, recomendada)
    HoistingSe puede usar antes de declararla y "funciona" (confuso).Hay que declararla antes de usarla o da error.
    RedeclararSe puede declarar dos veces la misma variable.Error: se declara una vez y luego solo se reasigna.
     
    // Con var (válido, pero confuso)
edad = 18;
var edad;

var edad = 18;
var edad = 20;

// Con let (lo correcto)
let edad;
edad = 18;
edad = 20;
    Concepto clave

    JavaScript es débilmente tipado: no se indica el tipo de la variable y este puede cambiar (edad = '18' y luego edad = 18). Es posible, pero conviene evitarlo para no liarse.

    Autoevaluación

    Para definir una variable hoy día es más conveniente utilizar var que let. ¿Verdadero o falso?

    Falso. Se usa let: obliga a declarar antes de usar y no permite redeclarar, así que evita errores.

    1.3.1.- Conversiones de tipos de datos.

    JavaScript convierte tipos solo al operar, y no siempre como esperas. Con +, si uno de los operandos es una cadena, convierte el otro a cadena y los concatena. Se evalúa de izquierda a derecha:

console.log(4 + '7');       // '47' (cadena)
console.log(1 + 2 + '3');   // '33' (1 + 2 = 3, luego 3 + '3' = '33')

    1.4.1.- Algunos operadores de interés.

    Plantillas de cadenas (template string). Con comillas invertidas ` y las variables dentro de ${}. Además permiten escribir en varias líneas sin usar +.

    let nombre = 'Bob Esponja';
console.log(`Hola ${nombre}`);   // Hola Bob Esponja

    Desestructuración. Sacar valores de un array o de un objeto y guardarlos en variables de una vez.

    // Desde un array (por posición)
let [personaje1, personaje2] = ['Bob Esponja', 'Calamardo'];
console.log(personaje1);   // Bob Esponja

// Desde un objeto (por nombre de propiedad)
let personaje = { nombre: 'Bob Esponja', edad: 18 };
let { nombre, edad } = personaje;
console.log(edad);         // 18

    Operador condicional ? : (ternario). Es un if-else abreviado:

    (condicion) ? expresionV : expresionF;

let edad = 20;
console.log(edad >= 18 ? 'Mayor de edad' : 'Menor de edad');

    typeof. Dice de qué tipo es una variable o expresión.

    let indefinido;
console.log(typeof indefinido);   // undefined
console.log(typeof '5');          // string
console.log(typeof 5);            // number

    1.5.- Condiciones y bucles.

    Los programas, como nosotros a diario, toman decisiones (si pasa esto, hago aquello) y repiten acciones (hacer algo varias veces o hasta que se cumpla algo). Para eso están las estructuras de control y los bucles.

    1.5.1.- Estructuras de control.

    Dirigen el flujo del programa según una condición: una expresión que vale true o false.

    SentenciaCuándo se usa
    ifHacer algo solo si se cumple la condición.
    if - elseElegir entre dos caminos: uno si se cumple y otro si no.
    ? :Versión corta de if - else para devolver un valor.
     
    if (edad >= 18) {
    alert('Ya eres mayor de edad');
}

if (edad >= 18) {
    alert('Ya eres mayor de edad');
} else {
    alert('Aún eres menor de edad');
}

    Autoevaluación

    Es obligatorio que en una sentencia if siempre utilicemos la claúsula else. ¿Verdadero o falso?

    Falso. El else es opcional: un if puede ir solo.

    1.5.2.- Bucles.

    Repiten un bloque de instrucciones un número fijo de veces o mientras se cumpla una condición.

    BucleCuándo usarlo¿Se ejecuta al menos una vez?
    forSabes cuántas veces repetir.No (si la condición es falsa desde el principio)
    whileNo sabes cuántas veces: repite mientras se cumpla la condición.No
    do - whileComo while, pero comprueba la condición al final.Sí, siempre una vez
     
    // for: inicialización; condición; incremento
for (let i = 0; i <= 10; i++) {
    console.log(5 * i);
}

// while
let i = 0;
while (i <= 10) {
    console.log(5 * i);
    i++;   // sin esto, bucle infinito
}

// do - while
let j = 0;
do {
    console.log(5 * j);
    j++;
} while (j <= 10);
    Concepto clave

    Dentro del bucle algo tiene que hacer que la condición acabe siendo false. Si no, tienes un bucle infinito. Más adelante verás otras formas de recorrer colecciones: forEach, map, filter, reduce…

    Autoevaluación

    Un bucle for es imposible que se convierta en un bucle infinito ya que lleva implícita la sentencia de incremento. ¿Verdadero o falso?

    Falso. Si la condición nunca llega a ser falsa, es infinito. Por ejemplo, for (let i = 0; i >= 0; i++).

    Autoevaluación

    El uso del bucle for en el ejemplo es el más adecuado. ¿Verdaero o falso?

    Verdadero. Se sabe de antemano cuántas veces hay que repetir (del 0 al 10), que es justo el caso del for.
