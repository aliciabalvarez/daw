    1.- Características de la programación web.

    Antes de programar en el servidor, hay que entender qué pasa cuando abres una página web.

    Una página web es un fichero escrito en HTML: etiquetas que dicen qué es cada cosa (esto es un título, esto un párrafo, esto una tabla). El aspecto (colores, tipos de letra, márgenes) suele ir en otro fichero aparte, la hoja de estilos o CSS. El navegador descarga los dos y los junta para mostrarte la página.

    Esos ficheros están guardados en un servidor web: un ordenador con un programa (como Apache) que se queda esperando a que alguien le pida algo. Cuando escribes una dirección en el navegador pasa esto:

    1. Peticióntu navegador pide pagina.html
    2. Búsquedael servidor busca ese fichero
    3. Recuperaciónsi existe, lo coge
    4. Respuestate lo envía y el navegador lo muestra

    A esta forma de funcionar se le llama cliente-servidor: el cliente (tu navegador) es quien pide, y el servidor es quien atiende y responde.

    1.2.- Ejecución de código en el servidor y en el cliente.

    El código del servidor y el del navegador no compiten: se reparten el trabajo. Siguiendo con el correo web:

    • El servidor (PHP, por ejemplo) busca tus mensajes en la base de datos.
    • El navegador (JavaScript) te avisa al instante si intentas enviar un correo sin asunto, sin preguntar al servidor.

    Durante años, el JavaScript del navegador no podía pedirle datos al servidor. Si querías leer otro correo, el servidor tenía que fabricar una página entera nueva y el navegador la recargaba.

    Eso cambió con AJAX: una técnica que permite al JavaScript pedirle datos al servidor en segundo plano y cambiar solo un trozo de la página, sin recargarla. Pulsas un correo y aparece al momento, en la misma página.

    Además de elegir las piezas, hay que decidir cómo ordenar tu código. Lo habitual es separarlo en capas, cada una con un trabajo. Así, si cambias una, no rompes las demás, y si la aplicación crece, cada capa puede ir en un servidor distinto. La forma más común tiene 3 capas:

    Las capas son una forma de organizar el código, no programas distintos. PHP aparece en dos capas (la lógica y las consultas), y Apache no pertenece a ninguna: es solo el camarero que lleva y trae.

    2.1.1.- Selección de una arquitectura de programación web.

    No hay una plataforma mejor que las demás para todo. Se elige según el proyecto, respondiendo preguntas como estas:

    • ¿Es grande o pequeño? Para algo pequeño, AMP; para algo enorme de empresa, quizá Java.
    • ¿Qué lenguajes sé ya? ¿Merece la pena aprender uno nuevo para este proyecto?
    • ¿Gratis o de pago? Las soluciones comerciales tienen coste de licencias.
    • ¿Lo hago sola o en equipo? El equipo tiene que conocer la tecnología.
    • ¿Ya tengo un servidor o una base de datos, o puedo elegir libremente?
    • ¿Con qué licencia se va a distribuir la aplicación?

    2.2.- Integración con el servidor web.

    Este apartado responde a una sola pregunta: cuando el servidor web recibe una página que hay que ejecutar, ¿cómo se la pasa a quien sabe ejecutarla?

    Primero, un repaso: petición y respuesta

    El navegador y el servidor se hablan con HTTP, que es el "idioma" de la web. Funciona siempre igual:

    • Petición: el navegador pide algo ("dame productos.php") y, si hace falta, envía datos (lo que escribiste en un formulario).
    • Respuesta: el servidor devuelve el resultado (una página HTML, una imagen, un JSON…).

    El programa que recibe esas peticiones es el servidor web (Apache, por ejemplo). El problema es que Apache por sí solo solo sabe entregar ficheros tal cual. Si le piden un .html, lo envía y listo. Pero un .php no se puede enviar así: primero alguien tiene que ejecutar el código para obtener el HTML. Apache tiene que pasárselo a otro.

    Piénsalo como un restaurante

    El servidor web es el camarero: toma la comanda y lleva el plato a la mesa, pero no cocina. Quien cocina (ejecuta el código) es otro. Este apartado explica las distintas formas de organizar la cocina.

    Forma 1: CGI (llamar a un cocinero de fuera)

    CGI no es un programa ni un lenguaje: es un acuerdo, unas reglas que dicen cómo el servidor web le pasa los datos a otro programa y cómo ese programa le devuelve la página. Casi todos los servidores web lo entienden.

    Como la regla solo exige "recibe los datos y escribe el resultado como texto", el programa puede estar escrito en cualquier lenguaje: Perl, C, Python, bash… A esos programas se les llama guiones CGI.

    Su problema es la lentitud: por cada petición, el ordenador tiene que arrancar el programa desde cero (crear un proceso nuevo, es decir, ponerlo en marcha), ejecutarlo y cerrarlo. Es como si para cada plato el camarero llamara a un cocinero que viene de su casa, cocina y se vuelve a ir. Para acelerarlo se inventaron mejoras como FastCGI, que deja al cocinero esperando en vez de llamarlo cada vez.

    Forma 2: módulos de Apache (el cocinero vive en la cocina)

    Un módulo es un complemento que se instala dentro de Apache para ampliar lo que sabe hacer. Con el módulo de PHP (mod_php), el intérprete de PHP (el programa que entiende y ejecuta PHP) está dentro de Apache, siempre listo. Apache le pasa los .php directamente, sin llamar a nadie de fuera: mucho más rápido.

    Hay módulos para otros lenguajes: mod_python para Python y mod_perl para Perl.

    Esto es lo que usas tú

    Tu XAMPP funciona así: Apache con el módulo de PHP dentro. Por eso PHP casi nunca se ejecuta por CGI. Y por eso, si cambias php.ini, tienes que reiniciar Apache: PHP se carga junto con él.

    Forma 3: Java (un restaurante especializado)

    Java no se "enchufa" a Apache como PHP. Necesita su propio programa servidor, y hay dos tipos:

    • Contenedor de servlets: ejecuta los servlets y las páginas JSP (programas Java que generan páginas web; los verás en el apartado 2.3.2). El más conocido es Tomcat, gratuito y que además puede hacer de servidor web él solo, sin Apache.
    • Servidor de aplicaciones: hace todo lo anterior y más (por ejemplo, los EJB, piezas de Java para la lógica de aplicaciones grandes). Ejemplos: GlassFish, JBoss, WebSphere, WebLogic.

    Para la mayoría de proyectos basta con un contenedor de servlets como Tomcat; el servidor de aplicaciones completo solo hace falta en aplicaciones muy grandes.

    Forma 4: ASP.Net (el restaurante de Microsoft)

    Microsoft tiene su propio servidor web, IIS, que ya viene preparado para ejecutar páginas ASP y ASP.Net sin instalar nada aparte, y con herramientas para gestionar las aplicaciones.

    2.3.- Lenguajes.

    Los ordenadores no entienden directamente el código que escribimos: hay que traducirlo a instrucciones de máquina. Los lenguajes se diferencian en cuándo y cómo se hace esa traducción. Hay tres tipos:

    1. Lenguajes de guiones o scripting (traducción en directo)

    El código se guarda tal cual lo escribes, en un fichero de texto. Cada vez que alguien pide la página, un intérprete lo lee y lo ejecuta línea a línea, como un traductor simultáneo. Ejemplos: PHP, Perl, Python, ASP.

    2. Lenguajes compilados a código nativo (traducido del todo antes)

    Antes de usarlo, el código se traduce entero al "idioma" del procesador (código binario). En el servidor se guarda ya traducido y se ejecuta directamente. Es como un libro ya traducido a un idioma concreto: se lee rapidísimo, pero solo en ese idioma (ese tipo de procesador). Ejemplo: C. En la web se usan a través de CGI.

    3. Lenguajes compilados a código intermedio (traducido a medias)

    El código se traduce a un idioma intermedio que no depende del procesador. Luego, al ejecutarlo, se termina de traducir al idioma de la máquina concreta. Así funciona Java (servlets y JSP) y ASP.Net.

    Ese último paso suele hacerse con JIT (Just In Time, "justo a tiempo"): cuando se usa un programa, se traduce a código de máquina y se guarda el resultado, para no tener que traducirlo otra vez la próxima.

    2.3.1.- Código embebido en el lenguaje de marcas.

    Una página dinámica mezcla dos cosas: el HTML (la estructura de la página) y el código que genera lo que cambia. Hay dos formas de mezclarlos:

    A. El HTML metido dentro del código

    Escribes un programa y, con instrucciones de "escribir", vas soltando el HTML línea a línea. Así son los guiones CGI y los servlets de Java.

    #!/bin/sh
echo "Content-Type: text/html"
echo ""
echo "<html><body>"
echo "Prueba de guion bash CGI"
echo "</body></html>"
    B. El código metido dentro del HTML

    Escribes una página HTML normal y metes trocitos de código solo donde hace falta algo que cambia. Así es PHP, y también ASP y JSP. Se le llama código embebido ("incrustado").

    <body>
  El nombre del servidor es:
  <?php echo $_SERVER['SERVER_NAME']; ?>
</body>

    La forma B es mucho más cómoda: lo fijo se escribe en HTML normal y solo programas lo que cambia.

    • Java tiene las dos: los servlets (forma A, programas Java ya traducidos) y las JSP (forma B, Java dentro de HTML). La primera vez que alguien pide una JSP, se convierte automáticamente en un servlet y se guarda para las siguientes.
    • ASP.Net separa cada página en dos ficheros: uno con el HTML y otro con el código. Así el diseño y la programación quedan independientes.
    Importante

    La forma de mezclar HTML y código no depende de si el lenguaje es de guiones o compilado. PHP (guiones) y JSP (compilado) usan la forma B; un guion CGI en Perl (guiones) y un servlet (compilado) usan la forma A.

    Autoevaluación

    La relación entre la forma de ejecución de un lenguaje, y el método para integrarse con las etiquetas HTML de una página web es:

    No hay relación directa. PHP (guiones) y JSP (compilado a código intermedio) embeben código en el HTML; un guion CGI en Perl (guiones) y un servlet (compilado) meten el HTML dentro del código.

    4.- Conceptos básicos de programación web con PHP.

    PHP es un lenguaje de guiones pensado para hacer páginas web dinámicas metiendo el código dentro del HTML. Si conoces JavaScript o Java, su forma de escribir te resultará familiar.

    El código PHP siempre va entre <?php y ?>. Todo lo que está fuera se envía como HTML normal; lo de dentro se ejecuta y se sustituye por lo que produzca.

    El intérprete de PHP y Apache

    En XAMPP, PHP funciona como un módulo de Apache (mod_php): el intérprete está metido dentro de Apache. Además, existe el intérprete como programa suelto (php.exe), que es el que usa NetBeans. Son el mismo PHP y comparten configuración.

    Los ficheros de configuración

    Apache y PHP se configuran con ficheros de texto: httpd.conf para Apache y php.ini para PHP. La página phpinfo() te dice dónde está tu php.ini.

    Importante

    Como PHP va dentro de Apache, los cambios en php.ini no se aplican hasta que reinicias Apache (Stop y Start en el panel de XAMPP).

    Las opciones (directivas) de php.ini que más se usan:

    DirectivaQué controla, en sencilloValor recomendado
    short_open_tagSi se puede abrir PHP con la forma corta <? en vez de <?phpOff: la forma corta da problemas con XML. Usa siempre <?php
    max_execution_timeCuántos segundos como máximo puede tardar un script. Si se pasa, PHP lo corta, para que un error no deje el servidor colgadoPor defecto, 30
    display_errorsSi los errores se muestran en la páginaOn mientras programas; Off en una web publicada (no conviene que los visitantes vean tus errores)
    error_reportingQué tipos de errores se muestranE_ALL (todos) o E_ALL & ~E_NOTICE (todos menos los avisos leves)
    file_uploadsSi se pueden subir ficheros a la webOn si los necesitas
    upload_max_filesizeTamaño máximo de cada fichero subidoPor ejemplo, 1M (1 megabyte)
    post_max_sizeTamaño máximo de todo lo que se envía en un formulario (los ficheros y los demás campos juntos)Igual o mayor que upload_max_filesize
    Pista para las subidas

    Para subir un fichero de 5M tienen que dejarlo pasar las dos: upload_max_filesize (el fichero) y post_max_size (el envío completo). Si una de las dos es menor, falla.

    Actividad de repaso: verdadero o falso

    Caso 1: Para mi proyecto necesito subir PDF de hasta 5M. Las subidas serán todas por formularios (POST). He revisado upload_max_filesize = 15M. ¿Podré subir mis archivos?

    Falso (no está garantizado): con POST también manda post_max_size. Si es menor de 5M, la subida falla aunque upload_max_filesize sea 15M.

    Caso 2: Con short_open_tag = Off, ¿funcionará este código?
    <? $var=45; echo $var; ?>

    Falso. Con los delimitadores cortos desactivados, <? no se interpreta como PHP. Hay que usar <?php.

    Caso 3: Acabo de pasar mi proyecto PHP de producción a desarrollo y display_errors tiene el valor por defecto. ¿Lo he hecho bien?

    Verdadero. Por defecto suele estar a On, que es lo recomendado en desarrollo.

    4.2.- Literales, constantes, variables y tipos de datos.

    Un programa trabaja con datos: números, textos, verdadero o falso… Este apartado explica cómo se escriben y se guardan.

    Tu herramienta para mirar: var_dump()

    var_dump() te enseña qué tipo de dato es algo y cuánto vale. La usarás todo el rato para comprobar qué pasa en tu código.
    var_dump(45) → int(45): un número entero que vale 45.
    var_dump("HOLA") → string(4) "HOLA": un texto de 4 letras.

    Literales: datos escritos tal cual

    Un literal es un valor escrito directamente en el código: 32, 0.45, "HOLA", true.

    TipoCómo se escribeEjemplo
    Números enterosNormal, o en otras bases: octal (empieza por 0), hexadecimal (0x), binario (0b)1234, -123, 0x1A (= 26), 0b11111111 (= 255)
    Números con decimalesCon punto, o en notación científica1.234, 1.2e3 (= 1200)
    TextoEntre comillas simples o dobles'Hola', "Hola"
    Verdadero / falsoSin comillastrue, false

    ¿Comillas simples o dobles? No es lo mismo:

    Comillas simples '...'Comillas dobles "..."
    El texto sale tal cualPHP "lee" el texto y sustituye cosas especiales
    'Hola $nombre' → Hola $nombre"Hola $nombre" → Hola Alicia (pone el valor de la variable)
    Solo entiende \' (una comilla) y \\ (una barra)Entiende secuencias de escape: \n (salto de línea), \t (tabulador), \" (comillas), \$ (el símbolo $)…
     
    var_dump('Le dió p\'al pelo'); // la \' permite meter una comilla dentro

    Los saltos de línea y tabuladores no se ven en el navegador (el HTML los ignora), salvo que el texto vaya dentro de una etiqueta <pre>. Hay otras dos formas de escribir textos largos, HEREDOC y NOWDOC, que verás más adelante.

    Constantes: un nombre para un valor fijo

    Una constante es un nombre que le das a un valor que no va a cambiar. Si algún día cambia, solo lo modificas en un sitio. Se crean con define() y se escriben sin $, normalmente en mayúsculas.

    define('IVA', 0.21);
var_dump(IVA); // float(0.21)

    Variables: cajas con nombre

    Una variable es como una caja con etiqueta donde guardas un valor que puede cambiar. En PHP:

    • Siempre empiezan por $, seguido de una letra o _ (luego pueden llevar números): $nombre, $total_2.
    • No hay que declararlas ni decir de qué tipo son: se crean al darles un valor con =.
    • Su tipo depende de lo que guardes, y puede cambiar si guardas otra cosa.
    $mi_variable = 7;        // ahora es un número: int(7)
$mi_variable = "siete";  // ahora es un texto: string(5) "siete"

    Tipos de datos

    TipoNombre técnicoQué guardaEjemplo
    BooleanoboolSí o no: true o false. Un número cuenta como true salvo el 0$activo = true;
    EnterointNúmeros sin decimales$edad = 30;
    Real o decimalfloatNúmeros con decimales$precio = 9.99;
    CadenastringTexto$nombre = "Alicia";
    Nulonull"Esta caja está vacía": no tiene valor$x = null;

    Cambiar de tipo

    Si operas con tipos distintos, PHP los convierte solo a uno común: 3 + 2.3 da 5.3 (decimal). También puedes forzar la conversión tú, poniendo el tipo entre paréntesis delante. Eso se llama casting:

    $resultado = 3 + (int) 2.3; // (int) quita los decimales: 3 + 2 = int(5)

    Conversiones que puedes forzar: (int), (bool), (float), (string), (array), (object).

    Y para preguntar de qué tipo es algo, hay funciones que responden true o false: is_int(), is_float(), is_string(), is_bool(), is_array(), is_object() y is_numeric() (que acepta números y también textos con un número dentro, como "23").

    var_dump(is_int(23));   // bool(true)
var_dump(is_int('23')); // bool(false): es un texto, aunque contenga un número

    ++ antes o después: no es lo mismo

    4.4.- Evaluación de expresiones.

    Evaluar una expresión es calcularla: PHP la resuelve y la sustituye por su resultado. Si la expresión es solo un valor (5) o una variable ($x), el resultado es ese valor. Si tiene operadores, hay que saber en qué orden se calculan.

    El orden: precedencia y asociatividad

    • Precedencia: qué operadores van primero, como en matemáticas (la multiplicación antes que la suma). El manual de PHP tiene la tabla completa.
    • Asociatividad: si dos operadores tienen la misma prioridad, en qué dirección se resuelven: de izquierda a derecha o al revés.
    • Los paréntesis siempre van primero. Úsalos cuando dudes: hacen el código más claro.
    !(5 - 3 * 2 / 2 > 7 % 3)
// 3 * 2 = 6      (* y / tienen la misma prioridad: de izquierda a derecha)
// 6 / 2 = 3
// 5 - 3 = 2
// 7 % 3 = 1
// 2 > 1 = true
// !true = false  → resultado: bool(false)

    La asignación = va de derecha a izquierda. Por eso puedes dar el mismo valor a varias variables de golpe:

    $a = $b = $c = 10; // primero $c = 10, luego $b = 10, luego $a = 10

    Cortocircuito: PHP no calcula lo que no necesita

    Con && y ||, a veces el primer valor ya decide el resultado, y PHP ni mira el segundo:

    • && (Y): si lo primero es false, el resultado ya es false.
    • || (O): si lo primero es true, el resultado ya es true.
    var_dump(false && 1/0);  // bool(false): no llega a dividir por cero
var_dump(true || 1/0);   // bool(true): tampoco
var_dump(1/0 || true);   // ERROR: la división va primero y sí se calcula

    El ternario funciona parecido: según la condición, solo calcula una de las dos opciones.

    Valores por defecto: ?: frente a ??

    Los dos hacen lo mismo: “si $path no sirve, usa '/'”. La diferencia está en qué consideran “no sirve”.

    OperadorUsa el valor por defecto cuando…Ejemplo
    ?: (ternario corto)El valor es "falso": false, 0, "", null…$path ?: '/'
    ?? (fusión de null)El valor es solo null o no existe$path ?? '/'
     
    $path = "/inicio";
$path ?: '/'   // "/inicio" → tiene algo útil
$path ?? '/'   // "/inicio" → existe y no es null

$path = null;
$path ?: '/'   // "/" → null no vale
$path ?? '/'   // "/" → es null

$path = "";
$path ?: '/'   // "/" → un texto vacío no vale para ?:
$path ?? '/'   // ""  → para ?? sí vale: no es null

    Regla práctica: usa ?? cuando un dato puede no llegar (un campo de formulario, un parámetro de la URL) y ?: cuando también quieras sustituir valores vacíos como 0 o "".

    La expresión match

    match mira un valor y devuelve un resultado distinto según cuál sea, como una tabla de equivalencias. Puedes poner varios valores en la misma opción, separados por comas, y un default para "cualquier otro caso".

    $nota = 7;
$texto = match ($nota) {
    1, 2  => "Muy deficiente",
    3, 4  => "Insuficiente",
    5     => "Suficiente",
    6     => "Bien",
    7, 8  => "Notable",
    9, 10 => "Sobresaliente",
    default => "Nota incorrecta",
};
// $texto vale "Notable"
    Ojo con match

    Compara con ===: el valor y el tipo tienen que coincidir. Si $nota fuera el texto "7" (por ejemplo, venido de un formulario), no encajaría con el número 7 y saldría "Nota incorrecta". Conviértelo antes con (int).
